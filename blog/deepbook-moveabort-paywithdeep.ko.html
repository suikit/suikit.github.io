DeepBook V3 MoveAbort code 3 — 모든 봇이 겪는 pay_with_deep의 조용한 실패

DeepBook V3에 지정가 주문을 넣었는데 트랜잭션이 풀 모듈 어딘가에서 MoveAbort ... 3으로 중단됩니다. 에러 문자열도, 힌트도 없이 숫자 코드 하나뿐입니다. 봇을 운영한다면 주문이 조용히 실패하는 가장 흔한 방식입니다.

코드 3의 실제 의미

DeepBook V3는 수수료를 DEEP 토큰 또는 풀의 quote/base 코인으로 청구할 수 있습니다. 선택은 주문 호출의 플래그입니다:

tx.moveCall({
  target: `${DEEPBOOK_PACKAGE}::pool::place_limit_order`,
  arguments: [ pool, balanceManager, /* …, */ payWithDeep /* bool */, /* … */ ],
});

pay_with_deep = true이면 수수료는 BalanceManager (트레이딩용 자금이 들어있는 온체인 오브젝트)의 DEEP 잔액에서 빠져나갑니다. 이 잔액이 수수료를 못 감당하면 abort가 발생합니다:

  • DEEP 자체가 부족. manager에 SUI와 USDC는 넣었지만 DEEP를 입금한 적이 없는 경우 — 새 세팅에서 아주 흔한 실수입니다.
  • DEEP는 있지만 잠겨 있음. 미체결 주문은 잔액을 잠그는데, 다른 주문의 수수료로 이미 잡힌 DEEP도 포함됩니다. free DEEP ≠ total DEEP. 50 DEEP를 보유하고도 0.5 DEEP 수수료로 실패할 수 있습니다.

두 번째 경우가 치명적입니다 — 며칠 잘 돌다가 미체결 주문이 쌓여 잠긴 DEEP이 늘면서 갑자기 abort가 시작됩니다. 코드는 그대로인데 잔액이 수수료 기준선 아래로 내려간 것뿐입니다.

abort 전에 감지하기

우리가 제공하는 수정은 사전 체크 + 자동 폴백입니다:

// 주문 tx를 만들기 전에
const deep = await manager.balances(DEEP_TYPE);           // { free, locked }
const feeEstimate = estDeepFee(order);                    // 풀 수수료 파라미터로 산출
const payWithDeep = deep.free > feeEstimate * SAFETY;    // 약 3배 버퍼

if (!payWithDeep) {
  // 대신 풀 코인으로 수수료 지불 — 주문은 그대로 체결됨
}

pay_with_deep = false로 바꾸면 같은 주문이 성공합니다 — 수수료는 주문 자체의 대금(풀의 quote/base 코인)에서 차감됩니다. 자산 기준 수수료는 약간 달라지지만, 주문이 살아있는 것이 깔끔한 실패보다 낫습니다.

우리가 정착시킨 운영 규칙

  • DEEP 버퍼 유지. 예상 미체결 수수료 부하의 약 3배를 manager에 두어 pay_with_deep=true를 유지(풀에 따라 DEEP 수수료가 더 쌀 수 있음).
  • 플래그를 하드코딩하지 않기. 총 잔액이 아니라 free 잔액 기준으로 주문마다 평가.
  • 어느 경로로 체결됐는지 로깅. "(deep)" vs "(pool-coin)" 구분은 나중에 수수료 회계를 훨씬 쉽게 합니다.
  • free뿐 아니라 locked를 보기. 몇 주 잘 돌다가 abort가 시작되면 locked DEEP부터 확인 — 미체결 주문 누적이 범인입니다.

결과

사전 체크 하나가 가장 흔한 조용한 실패를 무력화했습니다: 봇이 부족분을 감지하고 수수료 자산을 바꿔도 주문은 체결됩니다. 봇이 코드 3으로 abort된다면, 다른 무엇보다 먼저 manager의 free DEEP을 확인하세요.
